# People and learning dashboards

Administrators have separate searchable, paginated student and teacher columns. Profiles show account status, connected Google/password sign-in methods (never the password or Google identifier), recorded session date, student grades and question-level responses, correct answers, marking guides and feedback. Teacher profiles include recent authored assessments and classrooms.

Teachers get Student Progress in their dashboard. A teacher can access students enrolled in their classrooms or with attempts on their own assessments. Only that teacher's assessments contribute to the student's history, answer review and topic analysis. Administrators can review across teachers. Students cannot call these educator APIs.

Topic analysis uses up to thirty recent fully graded attempts and labels missing mappings explicitly. Topic/chapter is a separate optional question field; measurement units such as N or m/s² are never treated as chapters. Existing snapshots are preserved. Analytics project only necessary metadata inside PostgreSQL, avoiding full diagrams and question bodies in profile aggregation. History is paginated; review loads one processed attempt on demand.

Educators can assign an existing published quiz or a private revision quiz reusing graded missed questions, with a chosen class, optional deadline and up to twenty questions. A private personal-practice classroom enrolls only the selected student. Teachers cannot assign another teacher's quiz. Revision request IDs are scoped to educator and student to prevent duplicate quiz creation on replay. Selection considers up to sixty missed items from the recent thirty-attempt sample and deduplicates identical questions. This is evidence-based reuse, not AI-generated new practice or a certified mastery model.

Administrator account controls require an explicit Save for role/status changes and revoke prior sessions. Admins may expire sessions or create an audited single-use password-reset link for an active student/teacher. The link expires in thirty minutes, works without an email provider, and allows the account owner to choose a new website password. Existing passwords are never exposed. Google passwords remain managed by Google. Reset tokens are stored only as hashes, omitted from logs/audits, and the link response is not cacheable. Reset links must be shared privately by the human administrator.

Validation: 45 regression tests passed, including six new database-backed people/access/revision/recovery checks; production build, type checking and lint passed before final visual refinements. Desktop two-column layout, mobile profile width, light/dark styles, wrong-answer filter and profile data were inspected using isolated test fixtures. Latest CI and deployment state should be checked with the accompanying release PR.
Follow-up reliability: revision questions are deduplicated across shuffled option order and regenerated option IDs. The assignment form retains the same request ID after a connection failure and locks its fields during submission. Image builds preserve required non-root asset permissions without recursively changing ownership of the complete dependency tree. This removes the redundant slow build step observed during production release. Regression suite now contains 46 tests.
